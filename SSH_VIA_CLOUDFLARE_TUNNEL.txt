STEP 3: ONCE CONNECTED - DATABASE RESTORE
================================================================================

If SSH works, you'll see a prompt like:
  $ 
  or
  user@server:~#

Then run these commands:

1. Check current database:
   ─────────────────────────
   sudo -u postgres psql -l
   # Look for SGCTECHAI database

2. Create backup of current database (SAFETY):
   ────────────────────────────────────────────
   sudo -u postgres pg_dump -d SGCTECHAI -F c -f ~/sgctechai_backup_$(date +%Y%m%d_%H%M%S).dump
   # This creates a safety backup

3. Upload your dump file (FROM ANOTHER TERMINAL, not in SSH):
   ───────────────────────────────────────────────────────────
   PowerShell:
   scp -i C:\Users\USER\.ssh\id_rsa C:\odoo19\backups\sync_to_remote_20260106_145050.dump USER@odoo.scholarixglobal.com:~/
   
   Or use WinSCP (GUI):
   https://winscp.net

4. Back in SSH, drop existing database:
   ────────────────────────────────────
   sudo -u postgres psql -c "DROP DATABASE IF EXISTS SGCTECHAI;"
   sudo -u postgres psql -c "CREATE DATABASE SGCTECHAI OWNER odoo;"

5. Restore the dump:
   ─────────────────
   sudo -u postgres pg_restore -d SGCTECHAI -v ~/sync_to_remote_20260106_145050.dump
   # This will take 5-10 minutes

6. Restart Odoo:
   ──────────────
   sudo systemctl restart odoo
   # Wait 15 seconds

7. Verify data:
   ────────────
   sudo -u postgres psql -d SGCTECHAI -c "SELECT COUNT(*) FROM crm_lead; SELECT COUNT(*) FROM crm_tag;"
   # Should show: 8912 leads, 13 tags

8. Check Odoo logs:
   ────────────────
   sudo tail -f /var/log/odoo/odoo-server.log
   # Watch for any errors (Ctrl+C to exit)

================================================================================
TROUBLESHOOTING
================================================================================

"Permission denied (publickey)"
  → SSH key not trusted by server
  → Solution: Make sure you're using the correct key
  → Or ask provider to add your key

"No such file or directory"
  → Key path is wrong
  → Solution: Use full path C:\Users\USER\.ssh\id_rsa

"Connection refused"
  → Server SSH daemon not running
  → Solution: Contact provider

"Passphrase for key"
  → Your SSH key has a password
  → Solution: Enter the password you set when creating the key
