Remote SSH Access via Cloudflare Tunnel

Date: January 7, 2026

Purpose: One source of truth to connect to odoo.scholarixglobal.com, run maintenance safely, and restore the SGCTECHAI database (8,912 CRM leads).

TL;DR (Happy Path)

  1. In Cloudflare Zero Trust → Access → Tunnels → select the active tunnel → Public Hostname: Subdomain ssh, Domain odoo.scholarixglobal.com, Service ssh://localhost:22. Save.
  2. Terminal A (keep open):
    "C:\odoo19\tools\cloudflared.exe" access tcp --hostname ssh.odoo.scholarixglobal.com --listener 127.0.0.1:2222
  3. Terminal B:
    ssh -i C:\Users\USER\.ssh\id_rsa -p 2222 odoo@127.0.0.1
  4. Maintenance: backup → stop Odoo → restore/run tasks → start Odoo → verify (see below).

Prerequisites

  • SSH key on your machine (e.g., C:\Users\USER\.ssh\id_rsa or id_ed25519).
  • cloudflared.exe at C:\odoo19\tools\cloudflared.exe.
  • Cloudflare Tunnel with a Public Hostname mapped to SSH (ssh.odoo.scholarixglobal.com → ssh://localhost:22).
  • Remote SSH user (e.g., odoo); your public key must be on the server.

Install / Login Cloudflared (one time)

1) Download (portable already placed)

Binary is stored at C:\odoo19\tools\cloudflared.exe. If missing, download latest from Cloudflare releases.

2) Login

"C:\odoo19\tools\cloudflared.exe" tunnel login

Finish browser auth; cert is written to C:\Users\USER\.cloudflared\cert.pem. If a stale cert exists, back it up then re-run login.

3) Verify tunnels

"C:\odoo19\tools\cloudflared.exe" tunnel list

Example active tunnel: odoo-tunnel1 (ID e2b9e7e7-eff3-408c-8bba-af3a43aa85bf).

Cloudflare Dashboard Setup

  1. Zero Trust → Access → Tunnels → select the active tunnel (odoo-tunnel1).
  2. Public Hostnames → Add:
    • Subdomain: ssh
    • Domain: odoo.scholarixglobal.com
    • Service: ssh://localhost:22
  3. Save and wait ~1 minute. Remove any old hostnames that pointed the root domain to SSH to avoid conflicts.

Connect via Cloudflare Access TCP

1) Start listener (keep open)

"C:\odoo19\tools\cloudflared.exe" access tcp --hostname ssh.odoo.scholarixglobal.com --listener 127.0.0.1:2222

2) SSH through listener

ssh -i C:\Users\USER\.ssh\id_rsa -p 2222 odoo@127.0.0.1

Use id_ed25519 if that is your key; adjust username if needed. Ensure the path uses backslashes (or /c/Users/USER/.ssh/id_rsa in Git Bash) to avoid the C:UsersUSER.sshid_rsa path error.

If you get connection refused: confirm the Public Hostname maps to ssh://localhost:22 and the listener is still running.

File Transfer

  • SCP (run outside SSH): 
    scp -i C:\Users\USER\.ssh\id_rsa C:\odoo19\backups\sync_to_remote_20260106_145050.dump odoo@ssh.odoo.scholarixglobal.com:~/

    If using the Access TCP listener, add -P 2222 and host 127.0.0.1 instead.

  • WinSCP (GUI): Protocol SFTP, Host ssh.odoo.scholarixglobal.com, User odoo, Key C:\Users\USER\.ssh\id_rsa.

Maintenance Workflow (once connected)

1) Safety backup

sudo -u postgres pg_dump -d SGCTECHAI -F c -f ~/sgctechai_backup_$(date +%Y%m%d_%H%M%S).dump

2) Stop Odoo

sudo systemctl stop odoo

3) Restore / maintenance

  • Restore example:
    sudo -u postgres pg_restore -d SGCTECHAI -c -v ~/sync_to_remote_20260106_145050.dump
  • Other tasks: apply updates, clean logs, etc., while Odoo is stopped.

4) Start Odoo

sudo systemctl start odoo

5) Verify

  • Counts:
    sudo -u postgres psql -d SGCTECHAI -c "SELECT COUNT(*) FROM crm_lead; SELECT COUNT(*) FROM crm_tag;"
  • Expect ~8,912 leads, 13 tags after restore.
  • Logs:
    sudo tail -50 /var/log/odoo/odoo-server.log

Troubleshooting

  • Permission denied (publickey): use the correct key path; ensure your public key is on the server.
  • Connection refused on 127.0.0.1:2222: listener stopped or hostname not mapped to SSH in Cloudflare.
  • Missing/invalid cert: rerun cloudflared tunnel login (backs up old cert.pem first if needed).
  • Path error (C:UsersUSER...): wrap the path in quotes and keep backslashes, or use /c/Users/USER/.ssh/id_rsa in Git Bash.
  • Outdated cloudflared warning: upgrade when convenient; current portable version 2024.12.0 works.
